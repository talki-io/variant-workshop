## 1. 一句话定位

**内部「出稿加速器」，不是「爆款自动机」。**

输入素材员的历史爆款（40–50 条、多账号）+ 自动采集的印尼股市新闻，产出**有真人味、贴热点、过合规底线**的文案变体草稿，供素材员选改。

**人始终在选稿与合规环节。** 系统的学习闭环定位为「弱学习」，不承诺自动变聪明。

## 3. 设计总原则

1. **提示工程路线，不做模型训练。** 历史爆款仅 40–50 条，够做 few-shot / 检索 / 风格锚定，不够训练任何模型或跑统计学习。
2. **自进化靠「隐式行为信号」。** 用户拿变体、选新闻、导出、编辑——这些他本来就要做的动作，就是最真实的反馈。显式评价只作可选加分，永不作为系统进化的必要条件。
3. **40–50 条爆款是「离线真值锚」。** 一次性（及周期性）离线提炼出模式库 + 语感指纹 + 风格参考向量 + 判别器 few-shot。这是全系统质量的地基。
4. **机器自评是主关卡，人在选稿与合规做最终把关。**

## 4. 已拍板、不要再推翻的决策

省得重新论证。

| 决策 | 结论 |
| --- | --- |
| 技术路线 | 提示工程 + 检索 + 规则，**零模型训练**（数据仅 40–50 条） |
| 反馈机制 | **隐式行为信号**为主 + bandit 探索；显式评价纯可选，不重度依赖用户打分 |
| 语感指纹 | 多账号 → **按调性分桶**独立建，绝不平均 |
| 质量指标 | **变体采用率**（导出/采用比例），不用爆款率 |
| 前端 | Ant Design 全家桶，**用现成组件不手写** |
| 采集工具 | **Playwright**（非 agent-browser）；RSS/API 优先 |
| 合规 | 禁词 + Haiku 语义 + 软提示 + 人工把关；快线保留一键确认 |
| 编排 | 一期轻量 async，预留 DAG 抽象；扩展再上 LangGraph |
| 模型 | Haiku（清洗/分类/语义合规）；Opus 4.8 或 Sonnet（生成/评审/去 AI 味）；快线走 Sonnet |

## 5. 一期必内建、不能省的底线

来自架构评审 §8：

- 禁词硬拦截 + **Haiku 语义合规兜底**（`architecture.md` §3 M6-3）
- 抓取内容抗注入：不可信数据隔离/转义（§3 M3/M5）
- M6 重写**迭代上限 2–3 次 + 超限降级**（§3 M6-1）
- **golden 集接 CI 门禁**：prompt/模型变更必过回归才上线（§8）
- 密钥托管 + 轮换；抓取源 ToS/robots 确认（§7）
- 成本配额/限流（§6）

## 6. 模块建设顺序（从地基往上）

1. **离线校准层**（最先，是全系统地基）—— 拆 40–50 条爆款 → 模式库 + 多调性语感指纹（按账号聚类，绝不平均）+ 风格参考向量 + 去 AI 味判别器 few-shot + golden 评测集。
2. **数据底座** —— Postgres + pgvector；建表：新闻/热点卡/模式库/风格向量/变体/权重表/token/埋点。
3. **采集 + 清洗（M1 → M3）** —— RSS/搜索 API 优先，Playwright 兜 JS 站；M3 含抗注入。
4. **生成 + 评审（M5 → M6）** —— 对话先指定目标账号/调性；M6 三层合规 + 重写迭代上限。
5. **前端 + 鉴权** —— 双角色。
6. **成本护栏（一期必含）** —— token 记录 + 看板 + 配额/限流。
7. **反馈埋点 + bandit** —— 隐式行为埋点；ε-greedy 先粗后细；奖励含合规惩罚项。
